## [Unreleased]

### Исправлено
- **Изоляция от личных конфигов yt-dlp**: все вызовы yt-dlp получили `--ignore-config`. Раньше пользовательский конфиг yt-dlp мог молча менять поведение скрипта (вплоть до `--simulate` или `--exec`), а скрипт рапортовал об успехе.
- **Честный успех**: в режиме видео+аудио код возврата 0 больше не считается успехом сам по себе - скрипт проверяет, что обещанный файл действительно создан.
- **Крах на битом cookie-файле**: переполнение при разборе аномально длинного `expiry` больше не роняет скрипт (`[int64]::TryParse` вместо прямого приведения).
- **Папка вместо файла**: проверки компонентов используют `-PathType Leaf` - каталог с именем `cookies-youtube.txt` или `yt-dlp.exe` больше не проходит как установленный компонент.
- **Скрытые файлы**: подбор свободного имени и поиск результата учитывают скрытые файлы (`-Force` у `Get-ChildItem`).
- **Диагностика онлайн-проверки cookies**: ошибка yt-dlp без cookie-паттернов (видео удалено/приватное) больше не маскируется под "cookies нерабочие".
- Убрано мёртвое условие в валидации `watch`-URL.

### Улучшено
- При ошибке скачивания выводится подсказка обновить yt-dlp (`-Setup -Force`) - самая частая причина сбоев по опыту (см. гайд по 4K).
- Определение результата в режимах `-Video`/`-Audio` устойчивее: сортировка по времени изменения, исключение остатков загрузчика (`.part`, `.ytdl`).
- Проверка версии yt-dlp валидирует форму ответа `--version` (диагностика сломанного exe не сравнивается с тегом GitHub).
- Скрипт нейтрализует `PSNativeCommandUseErrorActionPreference` сессии, чтобы обработка кодов возврата yt-dlp работала в любом окружении.
- Пунктуация консольного вывода приведена к стандарту проекта (дефис вместо длинного тире).

### Документация
- Добавлен гайд [docs/4k-po-token.md](docs/4k-po-token.md): как получить 4K, при чём тут PO Token и SABR, настройка локального bgutil-провайдера, региональный доступ (DPI/VPN). Главный вывод - при `403 Forbidden` или «только 1080p» первым делом обновлять yt-dlp (`-Setup -Force`).
- README: в раздел устранения неполадок добавлен пункт про 1080p-вместо-4K и HTTP 403.

## [2.0.1] - 2026-06-28

Патч надёжности и корректности. Без новых функций и без ломающих изменений.

### Исправлено
- **Режим `-Video`**: селектор `bv*` заменён на `bv`. Раньше `bv*` мог выбрать формат, *содержащий* видео вместе со звуком, что нарушало заявленный режим "видео без аудио". `bv` гарантирует поток только с видео (video-only).
- **Режим `-Mp4`**: ограничения `[vcodec^=avc1][height<=1080]` теперь применяются ко всем веткам селектора. Раньше последний fallback `b[ext=mp4]` мог вернуть не-H.264 или поток выше 1080p вопреки контракту совместимости.
- **Режим `-Audio`**: убран мёртвый fallback в `251/ba/bestaudio`. В yt-dlp `ba` и `bestaudio` - один и тот же алиас, поэтому третий вариант никогда не срабатывал. Теперь `251/ba/b` (добавлен корректный финальный fallback на комбинированный поток).

### Улучшено
- **Установка**: вокруг `Invoke-WebRequest` отключается индикатор прогресса (`$ProgressPreference = 'SilentlyContinue'`) - это убирает накладные расходы на его отрисовку при скачивании крупного ffmpeg-архива и не засоряет вывод.
- **Безопасность установки**: временная папка распаковки получает уникальное имя с GUID-суффиксом вместо удаления предсказуемой `_tmp_ytdlp_setup` (исключает риск затереть чужую папку с таким именем).
- **Надёжность проверки версий**: добавлен `.Trim()` при сравнении локальной и удалённой версий yt-dlp.
- **Кодировка**: добавлен UTF-8 BOM к скрипту для корректного чтения кириллицы и эмодзи на Windows.
- **Стиль кода**: функции переименованы под одобренные глаголы PowerShell (`Download-File` -> `Save-File`, `Ensure-Setup` -> `Initialize-Setup`).

### Документация
- README синхронизирован с фактическим поведением скрипта: обновлены форматные селекторы, объяснена разница `bv*` / `bv` / `ba` / `b`, `ffprobe.exe` явно помечен как опциональный.

## [2.0.0] - 2026-02-02

### Добавлено
- Режим `-Mp4`: скачивание в универсальном формате H.264 + AAC (макс. 1080p) для ТВ, телефонов и старых плееров.
- Режим диагностики (запуск без параметров): статус компонентов, проверка cookies, справка.
- Расширенная валидация URL: `channel/ID/live`, `c/Name/live`, `user/Name/live`, `clip/CLIP_ID`, `youtube-nocookie.com`.

### Исправлено
- Cookies с префиксом `#HttpOnly_` больше не отбрасываются как комментарии.
- Корректное вычисление имени скачанного файла в режимах `-Video` / `-Audio`.
- Фильтрация ключевых cookies по домену `.youtube.com`.

### Улучшено
- Парсинг URL через `[System.Uri]` вместо регулярных выражений.
- `ffprobe.exe` сделан опциональным (предупреждение вместо блокировки).
- O(n) парсинг cookies вместо O(n^2) на больших файлах.
- Полностью переработанная документация.

## [1.0.0] - 2026-01-09

### Добавлено
- Первый стабильный релиз.
- Режим автоматической установки компонентов (`-Setup`).
- Три режима скачивания: полное видео (MKV), только видео, только аудио.
- Валидация YouTube URL и проверка cookies (локальная и онлайн).
- Проверка актуальности версии yt-dlp через GitHub API.
- Документация на русском языке, лицензия MIT.
